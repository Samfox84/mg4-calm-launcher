===============================================================================
1. WHAT THIS IS AND WHY IT EXISTS
===============================================================================
The MG4 (MG Motor's electric hatchback) ships with SAIC's stock Android head-
unit software. The stock launcher/home screen is busy and visually noisy. This
project replaces the HOME experience with a custom Android launcher ("Calm
Launcher") designed around calm, low-stimulation, predictable UI  built by and
for a driver with AuDHD who is easily overwhelmed by cluttered, flashing,
inconsistent interfaces.

Design philosophy (keep this in mind for any change):
  * Calm, quiet, consistent. No flashing, no noise, minimal motion.
  * Soft optional UI sounds (sonification channel  never ducks music).
  * Everything in predictable places; grouping over density.
  * The map can be a full-screen background with controls floating over it.
  * Nothing should "pop up" and grab attention unless the driver asked for it
    (hence the big effort to suppress the stock HVAC pop-up).
  * Graceful degradation: if a feature's hardware/endpoint is missing, do
    nothing silently rather than erroring.

It is NOT a full OS replacement. It replaces the home/launcher surface and adds
a set of conveniences that talk to the car's existing services. The instrument
cluster is a separate module (see LIMITATIONS).


===============================================================================
2. TARGET HARDWARE & FIRMWARE
===============================================================================
  * Car:            MG4 EV (MG Motor / SAIC).
  * Head unit OS:   Android 9 (API level 28).
  * SoC:            MediaTek MT2712.
  * Stock software: SAIClauncher.apk (SAIC infotainment HMI).
  * Firmware baseline the main build targets: SWI68 (EU/UK, ~MY2022-23, R73).
  * Variants also tracked: SWI69, SWI132, SWI133 (see VARIANTS).
  * Instrument cluster: a separate IPK module, reachable only over SIPS. It is
    NOT addressable from an Android app  see LIMITATIONS.

The launcher runs as a privileged system app:
  * sharedUserId = android.uid.system  (so it can talk to car services and
    toggle system settings such as ADB).
  * Because of the shared system UID, it MUST be signed with the platform key
    (keys/platform.p12) and installed as a system/privileged app.

4. BUILD & RELEASE PROCESS
===============================================================================
Build command:
    ./build.sh

Requirements: Java (JDK 17+), python3, zip, unzip, curl.

What build.sh does, in order:
  1. Reads the version from version.properties.
  2. If tools/android.jar or tools/d8.jar are missing, downloads them from
     dl.google.com (Android platform-28_r06) and Google Maven (R8/D8 8.5.35),
     verifying SHA-256. If d8 lacks the signing library it also fetches
     apksig.jar (apksig 8.5.2). If a download fails it stops and tells you
     which file to supply manually.
  3. aapt2   compiles/links resources.
  4. javac   compiles Java to Java 8 bytecode.
  5. D8      dexes to classes.dex.
  6. Signs with v1 + v2 (+ v3) using keys/platform.p12.
     p12 password: android   alias: platform
  7. Output: build/MG4Launcher-<VERSION_NAME>.apk  (build/ is git-ignored).

Note: if the log token is missing (no tools/log-token.txt and no MG4_LOG_TOKEN
env var) the build still succeeds but warns that the APK will not upload logs.

---- Releasing / publishing (THE STANDING RULE: ALWAYS PUBLISH, NEVER SIDELOAD)
The car updates over-the-air by reading the repo's main branch. To ship a build:
  1. Bump VERSION_CODE and VERSION_NAME in version.properties.
  2. ./build.sh
  3. Copy the APK into releases/ :
        releases/MG4Launcher-<VERSION_NAME>.apk
  4. Update releases/latest.json:
        {
          "version": "1.0.5-calm.<N>",
          "apk":     "releases/MG4Launcher-1.0.5-calm.<N>.apk",
          "size":    <bytes of the apk>,
          "notes":   "<short human summary>"
        }
  5. Add a changelog entry to README.md (Italian "Versioni" + English
     "Changelog"), version numbers only, no dates.
  6. Commit and push to main.

The in-app updater reads main via raw.githubusercontent.com and the GitHub
contents API (default branch = main). Publishing to any other branch will NOT
be seen by the car. Old APKs in releases/ and old GitHub Releases are kept.

Commit convention (enforced by CLAUDE.md):
  * Commit message is always the single word:  Aggiornamento
  * Author:  a fixed author identity (defined in CLAUDE.md in the repo).
  * All change detail lives only in the README changelog, never the commit msg.

6. ARCHITECTURE OVERVIEW
===============================================================================
The launcher is a single privileged Activity-based Android app written in plain
Java with hand-built views (no XML layouts for the screens  views are
constructed in code via a small UI helper library, ui/Ui.java). There is no
Gradle/AndroidX dependency graph; it compiles directly with aapt2 + javac + D8.

Entry & lifecycle:
  * BootSplashActivity / StartupSplash  shown at launch; a welcome sound plays
    at startup (Sfx STARTUP = welcome.mp3).
  * MainActivity  the launcher home Activity. It builds the HomeView, wires up
    the service clients, starts watchers (dongle, dashcam auto-trigger, etc.),
    and hosts the overlay root used for confirmation dialogs.
  * HomeView  the main screen: map (as panel or full-screen background),
    car/vehicle panel, climate tiles, charging, the media now-playing panel,
    the Map/Media/CarPlay tab row, and the bottom bar.
  * AppsView  the "Apps" screen (swipe), grouped app grid + top-row shortcuts
    + a one-tap launcher-update bar.
  * SettingsView  all launcher settings (comfort toggles, update boxes, etc.).

Service/client layer (svc/) talks to the car:
  * Rpc + ServiceLink + VehicleClient  bind SAIC's vehicle service hub and make
    AIDL-style RPC calls (see CLIMATE/VEHICLE subsystem).
  * MediaClient / MusicPlayer / Subsonic  media state + the launcher's own
    library player (Navidrome/Subsonic).
  * Updater / LogUploader  self-update and GitHub uploads.
  * DashcamClient  360-camera-as-dashcam integration.
  * SysHvacPanel, JoystickMedia, AdbToggle, etc.  individual features.

UI state/preferences:
  * ui/Prefs.java  a thin SharedPreferences wrapper with a static get(Context)
    singleton; every feature flag has a getter/setter here.
  * ui/Theme.java  colours (t.text, t.sub, t.panel, t.accent, t.onAccent,
    t.track, ), light/night aware.
  * ui/Ui.java  view construction helpers (row/column/text/spacer, layout
    params lp()/lpWeight()/margins(), pressable backgrounds, dp()/tp() scaling).

8. SUBSYSTEM DEEP-DIVES
===============================================================================

-------------------------------------------------------------------------------
8.1  HOME SCREEN & FULL-SCREEN MAP BACKGROUND
-------------------------------------------------------------------------------
HomeView builds either:
  * Panel mode  map shown as one panel among others; media panel has a
    semi-opaque background.
  * Full-screen map background ("bgMap", pref mapBackground)  the live map
    fills the screen with a gradient scrim for legibility, and the UI panels
    float over it with transparent backgrounds.

Key bgMap behaviours (added over calm.9396):
  * Panel backgrounds (car panel, right panel, tabs, bottom bar) are set to null
    (transparent) when bgMap, so controls float over the map.
  * The media column is transparent and right-aligned (gravity END). The now-
    playing content is pushed into the right half by a leading weighted spacer
    in the media "body" row.
  * The source row (Radio/Library) keeps a right margin (~dp 180) so it sits
    just LEFT of the car's own system status bar (BT/Wi-Fi/4G) instead of under
    it. (Earlier versions clipped it under the status icons  fixed in calm.96.)
  * The Map/Media/CarPlay tab row moves to BOTTOM|END (bottom-right) in bgMap.
  * The "Map" tab is hidden in bgMap (the map is already the background).

Climate tiles on the home screen (via VehicleClient): rear defrost, blower
direction, ambient lighting (with a popup: toggle + colour + brightness
slider). Charging shows amps/volts text and an animation.

-------------------------------------------------------------------------------
8.2  MEDIA SUBSYSTEM  (the most-iterated area)
-------------------------------------------------------------------------------
Two distinct playback worlds feed one now-playing panel:

  A) CAR sources (MediaClient): radio, USB, Bluetooth, online (e.g. Amazon
     Music via the car), and CarPlay/Android Auto. State = source, playing,
     title/subtitle/art, and activeSrc (0 = nothing actually playing).

  B) The launcher's OWN library player: Navidrome/Subsonic via MusicPlayer +
     Subsonic. When it is playing, directAudio = true and applyDirectToPanel()
     owns the now-playing (title, artist, cover art via loadCoverInto).

The onMedia(State) method renders the panel. Critical rules learned the hard way
(do NOT regress these):
  * If the library (MediaSession, "libShowing") OR the direct player
    (directAudio) is playing, force radio = false. Otherwise the car's selected
    source can still be "radio" and the radio panels (FM/DAB, frequency, station
    list) draw OVER the music. (Fixed calm.95.)
  * When directAudio is active, onMedia must NOT touch the art tile  the cover
    is owned by applyDirectToPanel(), which loads asynchronously. If onMedia
    also sets the art it causes a 1-second cover-then-wave flicker. (calm.95.)
  * Idle (cold start, nothing playing): idleNP = activeSrc==0 && !radio &&
    !libShowing && !direct. When idle, the whole now-playing "body" is hidden
    (only Radio/Library remain so the driver can pick a source)  no stale
    "Amazon Music" + wave placeholder. (calm.94/95.)
  * The source label line shows the source ("ONLINE" etc.) but the "NAVIDROME"
    label was removed from the library now-playing. (calm.95.)
  * Album art: libraries show real cover art; when art is missing a neutral
    music-note icon is shown (R.drawable.ic_music), NOT the wave tile. The wave
    tile used to launch Amazon when tapped  that was removed.
  * selectTab(TAB_MEDIA) re-applies onMedia(media.last()) so switching from the
    full map back to Media refreshes the now-playing immediately instead of
    showing a stale track. (calm.94.)

The media panel also has a compact side/mini now-playing used by the map panel
and bottom bar; it follows the same idle/library rules.

-------------------------------------------------------------------------------
8.3  JOYSTICK / STEERING-WHEEL MEDIA CONTROL
-------------------------------------------------------------------------------
Root problem: the SAIC media service only handles transport for NATIVE car
sources, so the wheel joystick never controlled CarPlay/library playback.

JoystickMedia (called from WheelKeys) fixes this by dispatching media keys to
the currently active MediaSession:
  * Primary: MediaSessionManager.getActiveSessions(null) (needs the
    MEDIA_CONTENT_CONTROL permission), skipping SAIC/launcher packages.
  * Fallback: AudioManager.dispatchMediaKeyEvent via reflection, gated by
    MediaClient.isNativeSaicSource() so it doesn't double-fire on native
    sources.
  * Mapping: 5 = next, 4 = previous, 3 (short) = play/pause (long-press variant
    handled too).
Controlled by the "Joystick controls media" setting (pref joystickMedia,
default on).

-------------------------------------------------------------------------------
8.4  CLIMATE / VEHICLE CONTROL (VehicleClient)
-------------------------------------------------------------------------------
VehicleClient wraps Rpc with four descriptors: CHG (charging), AC (air/climate),
SET (settings), COND (conditioning). Codes are AIDL transaction numbers; an
unsupported-but-valid code returns -1, so unknown features self-disable without
crashing, and readException is caught.

Implemented controls:
  * Ambient lighting: on/off, colour, brightness, breathing mode, welcome
    light, plus an availability check. (Written via the SET/settingWrite path.)
  * Rear defrost toggle (AC codes).
  * Blower direction (AC codes).
  * Charging readback: amps and volts (stored in State, shown on the home
    charging tile).
Other-country "extra features": investigated; most are gated by firmware/region
coding that is SIPS-only and not reachable from the app. Driver-aid toggles were
explicitly declined by the owner.

Forward-collision / alert detection: CarProps reads the vendor property
AAD_FCW_WARNING_LEVEL_SIGNAL (id 557883745) via reflection on android.car.Car
(createCar -> connect -> getCarManager("property") -> getProperty). Needs
android.car.permission.CAR_VENDOR_EXTENSION. This is what the dashcam auto-
trigger watches.

-------------------------------------------------------------------------------
8.5  STOCK HVAC POP-UP SUPPRESSION (SysHvacPanel)
-------------------------------------------------------------------------------
Annoyance: turning the A/C or heating ON from fully OFF (via +/- or the centre
push) makes SAIC's SystemUI throw up its HVAC page over whatever you were doing.

Investigation found the trigger is in SystemUI's WindowAdapter: a handler message
(what=12, visible=0) calls showHVACPage() (window title "hvac page") on an air-
condition change. There is no setting to disable it, and killing it fully would
require patching SystemUI (the owner declined that).

Launcher-side mitigation (SysHvacPanel): while the "Stop the HVAC pop-up"
setting is on (pref hvacPopupSuppress, default on), the launcher detects the
"hvac page" window appearing over any app and closes it  with an ~8-second
grace window after the user themselves opened HVAC (so intentional opens aren't
fought). This hides most unwanted pop-ups but cannot stop them at the source.

-------------------------------------------------------------------------------
8.6  APPS SCREEN, ENGINEERING MODE, ADB
-------------------------------------------------------------------------------
AppsView groups app tiles by category with section headers:
  DRIVING / NAVIGATION / MEDIA & PHONE / SYSTEM & TOOLS.
Plus:
  * A top row of shortcuts (category "shortcut"): Android Settings and Android
    Files  pinned above the groups for quick reach.
  * A header update bar beside the "Apps" title: auto-checks on open
    (Updater.checkSilent) and shows "Up to date" or "Install <tag>"; one tap
    installs. Uses the same updater as Settings.
  * An Engineering-mode tile (SAIC EngineeringModeActivity; PIN 123456) exposing
    an ADB toggle (AdbToggle -> Settings.Global.ADB_ENABLED).

-------------------------------------------------------------------------------
8.7  DASHCAM (360 camera as dashcam)  DashcamClient
-------------------------------------------------------------------------------
Goal: use the user's 360-camera app (com.drivehub.kamera, the BETA build) with
a USB stick as a dashcam, and auto-upload footage around a collision.

Integration points (discovered by decompiling the 360 app):
  * Exported receiver DashcamEventTriggerReceiver accepts the broadcast
    com.drivehub.kamera.action.TRIGGER_DASHCAM_EVENT, which calls
    RecordingService.triggerEventSaveOrFutureOnly (saves a pre+post buffer).
  * Clip files: [0-9]{12,17}(_[FRXY])?.mp4 in the dashcam folder
    (Downloads/dashcam by default, USB override, events/ subfolder). 720x240
    grid frames.

DashcamClient behaviour:
  * ready() = 360 app installed AND dashcamDir() is a real directory; otherwise
    every operation no-ops (so "no USB stick" = do nothing, silently).
  * dashcamDir() auto-detects a USB "dashcam" folder under /storage/* or
    /mnt/media_rw/*, else falls back to Downloads/dashcam.
  * startAutoWatch() creates the Car via reflection, car.connect(), then polls
    the FCW property (557883745) ~every 700ms; on a collision warning it fires
    the event-save broadcast and uploads the clips.
  * Manual "send clip" button sits by the 360 button on the home screen; it
    uploads the current + previous recording.
  * Uploads go to a PRIVATE GitHub logs repo (configured via the upload token)
    the same way logs do: LogUploader.put(path, data) -> PUT /repos/.../contents/<path>
    with base64 body + Bearer token (422 = already exists). Clips are placed
    under dashcam/<date>/ and capped at ~90 MB (GitHub ~100 MB/file limit).
  * Controlled by the "dashcam auto-upload" setting (only shown if the 360 app
    is installed).

-------------------------------------------------------------------------------
8.8  UI SOUNDS (Sfx) + STARTUP SOUND
-------------------------------------------------------------------------------
Sfx plays soft UI sounds through a SoundPool on the ASSISTANCE_SONIFICATION /
CONTENT_TYPE_SONIFICATION channel  it never requests audio focus, so music is
never paused or ducked. All 20 sounds of the "Pacely" pack live in res/raw as
lowercase_underscore .mp3 files (Android resource names cannot contain hyphens):
  add, close, delete, done, drop, focus_start, gentle_error, hover, next_step,
  open, pause, pickup, step, swipe, tab, timer, toggle_off, toggle_on, undo,
  welcome.

Wired triggers:
  * STARTUP = welcome.mp3 at launch (MainActivity).
  * TAP = tab (general taps), OPEN/CLOSE on popups, DONE on confirms.
  * TOGGLE_ON / TOGGLE_OFF  different sound for a switch turning on vs off.
  * SWIPE on page change, ADD/DELETE where applicable.
The rest are bundled and available; a launcher simply has no natural moment for
a few of them (timer, focus_start, ). Sounds obey the existing calm-sounds
on/off setting. Startup sound is a touch louder (0.7) than the rest (0.45).

-------------------------------------------------------------------------------
8.9  DIPLAY INTEGRATION + UPDATE TOGGLE
-------------------------------------------------------------------------------
DiPlay (Samfox84/DiPlay-MG4-Plus) is a separate app: a wireless CarPlay receiver
that renders a map/turn-card on the instrument cluster. The launcher can detect
the installed DiPlay version and offer to update it from Settings, using the same
Updater machinery (installDiPlay()).

New in calm.94: a "Check for DiPlay updates" setting (pref diplayUpdateCheck,
DEFAULT OFF). When off, Updater.checkDiPlay() early-returns (no GitHub ping, no
update prompt) and the DiPlay box is hidden entirely in Settings  it only shows
the installed version, nothing more, and only if the toggle is on.

-------------------------------------------------------------------------------
8.10  SELF-UPDATE (Updater) + UPLOADS (LogUploader)
-------------------------------------------------------------------------------
Updater reads the repo's MAIN branch (raw.githubusercontent.com/.../main/ for
files + the GitHub contents API for the default branch):
  * checkSilent(repo, token, cb)  always calls back with the Release (newer or
    not). Used by the Apps header bar.
  * checkQuiet(...)  only calls back when a newer build with an APK URL exists.
  * check() / install(release, token)  the full flow; install triggers the
    Android package-install of the downloaded APK.
  * Release has fields incl. newer, apkUrl, tag, installed.
  * Separately detects + updates DiPlay (checkDiPlay / installDiPlay).
LogUploader.put(path, bytes) PUTs base64 to a private GitHub repo with a Bearer
token (used for diagnostics logs and dashcam clips).

10. VARIANTS  (SWI68 / SWI69 / SWI132 / SWI133)
===============================================================================
The project is primarily built for SWI68. Sibling firmware variants SWI69,
SWI132, SWI133 are tracked. Rules:
  * The graphics/UI must stay IDENTICAL across the variants.
  * Fixes should be applied the same way across all variants where possible.
Differences between variants are mostly firmware/region feature gating, much of
which is not reachable from the app.


===============================================================================
11. KNOWN LIMITATIONS (things that are NOT app-fixable)
===============================================================================
  * Instrument cluster size / feature-variant coding: the cluster is a separate
    IPK module reachable only over SIPS. Its physical size and the car's enabled-
    feature coding are NOT reachable from an Android app. (DiPlay draws onto the
    cluster via its own path; the launcher cannot resize or re-code it.)
  * Native Android Waze turn-by-turn: Waze running natively on the head unit does
    not broadcast navigation the way CarPlay apps do, so its directions can't be
    surfaced the way Apple Maps (via CarPlay) can. This is an app-side limitation
    of Waze, not something the launcher can add.
  * Stock HVAC pop-up: can only be MITIGATED from the launcher (close the window
    after it appears). Fully stopping it at the source needs a SystemUI patch,
    which the owner chose not to do.
  * Other-country car features: mostly SIPS/firmware-coded, not app-reachable.

13. HOW TO REBUILD OR MODIFY FROM SCRATCH (checklist for future-you / an AI)
===============================================================================
  1. Clone https://github.com/Samfox84/mg4-calm-launcher.
  2. Read CLAUDE.md (project rules) and this document.
  3. Supply the secrets that are NOT in git:
       keys/platform.p12  (the platform signing key  required to sign)
       tools/log-token.txt OR env MG4_LOG_TOKEN  (only if you want uploads)
     (tools/android.jar, d8.jar, apksig.jar auto-download in build.sh.)
  4. Make your change in the relevant subsystem (use the FILE MAP + deep-dives).
       - Respect the calm design philosophy (section 1).
       - For media changes, re-read section 8.2  the radio/library/direct/idle
         rules are easy to regress.
       - Keep graphics identical across SWI68/69/132/133 (section 10).
  5. Bump VERSION_CODE + VERSION_NAME in version.properties.
  6. ./build.sh  -> build/MG4Launcher-<VERSION_NAME>.apk
  7. Copy APK to releases/, update releases/latest.json (version/apk/size/notes),
     add a README changelog entry (IT + EN, version numbers only).
  8. Commit "Aggiornamento" (fixed author per CLAUDE.md) and push to MAIN.
     Cars auto-update from main. ALWAYS PUBLISH, never sideload.
  9. Never commit or print secrets (section 5).

If you are an AI assistant reading this to help: the repo is the source of
truth, build.sh is the whole toolchain, and the car updates itself from the
main branch's releases/latest.json. Work subsystem by subsystem, preserve the
media-panel rules in 8.2, and keep every build publishable (signed + in
releases/ + latest.json pointed at it).
